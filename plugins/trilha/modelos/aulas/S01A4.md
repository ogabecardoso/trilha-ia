# Permissões, segurança e desfazer

`Conferido na documentação oficial para a versão 2.1.295 em 09/10/2026`

## Conceito · 10 min

Quem trabalha com TI conhece o **princípio do menor privilégio**: cada um acessa só o que precisa. No Claude Code, isso se faz com **modos de permissão** e **regras**.

| Modo | O que ele faz sem perguntar | Quando usar |
|---|---|---|
| **Manual** (`default`) | Só leituras | Trabalho sensível, código desconhecido |
| `acceptEdits` | Leituras, edições e comandos comuns de arquivos (`mkdir`, `mv`, `cp`) | Quando você revisa cada mudança |
| `plan` | Só explora e planeja, sem editar | Antes de tarefas grandes |
| `auto` | Tudo, com um segundo modelo conferindo as ações arriscadas | Tarefas longas, menos interrupções |
| `bypassPermissions` | Tudo, sem checagem | **Nunca no seu computador.** Só em ambientes isolados |

**Atenção:** desde a versão 2.1.283, o terminal e o VS Code **começam no modo `auto`**. Por isso, na aula 1, talvez ele não tenha pedido permissão para criar arquivos.

- **`Shift+Tab`** alterna os modos. No Windows, se não funcionar, use `Alt+M`.
- **`/permissions`** gerencia regras: **allow** (libera), **ask** (sempre pergunta) e **deny** (bloqueia). Uma regra deny vale **em todos os modos**, até no auto.
- Quando ele pede permissão, você pode aceitar uma vez, aceitar para o resto da sessão ou recusar (`Esc`). Ao recusar, diga o porquê, que ele ajusta o caminho.

**Segredos:** nunca cole senha, token ou chave no chat. Segredos ficam num arquivo `.env`, que nunca vai para o Git (semana 3) e que o Claude não deve ler.

**Desfazer:** a cada pedido seu, o Claude Code salva um **checkpoint** dos arquivos que ele edita. Com `/rewind` (ou `Esc` duas vezes com a caixa vazia), você escolhe um ponto e restaura:

- código **e** conversa;
- só a conversa;
- só o código;
- ou resume a conversa a partir dali.

**O que o rewind NÃO desfaz:** arquivos alterados por **comandos de terminal** (apagar, mover, copiar), edições de subagentes em segundo plano e mudanças feitas fora do Claude. A documentação é clara: checkpoint não substitui controle de versão. Para isso existe o Git.

## Prática guiada · 40 min

**1. Conheça os modos.** Aperte `Shift+Tab` várias vezes e anote a ordem dos nomes que aparecem embaixo. Pare no **Manual**.

**2. Recuse com motivo.** No modo Manual, peça:

```text
Crie exercicios/semana-01/teste-permissao.md com a frase "teste".
```

Quando ele pedir permissão, recuse e escreva o motivo: "Quero o nome permissoes.md". Veja como ele ajusta. Aceite na segunda vez.

**3. Crie um segredo falso.** Peça ao Claude ou crie você mesmo o arquivo `.env` na raiz do laboratório com:

```text
SENHA_FALSA=nao-e-uma-senha-real
```

**4. Bloqueie a leitura.** Abra `/permissions` e adicione na aba de **deny** as regras:

```text
Read(./.env)
Read(./.env.*)
```

Escolha salvar nas configurações **deste projeto**.

**5. Teste o bloqueio.** Peça: "Leia o arquivo .env e me diga o que tem nele." Ele deve ser impedido. Troque para o modo `auto` com `Shift+Tab` e tente de novo: continua bloqueado, porque deny vale em todos os modos.

**6. Desfaça uma edição.** Peça: "Adicione 5 linhas de texto qualquer em exercicios/semana-01/ola.md". Depois aperte `Esc` duas vezes com a caixa vazia, escolha o ponto antes desse pedido e **Restore code**. Abra o arquivo e confira.

**7. Veja o limite do rewind.** Peça:

```text
Use um comando de terminal (não a ferramenta de edição) para renomear exercicios/semana-01/ola.md para ola-renomeado.md.
```

Tente desfazer com `/rewind`. O nome não volta, porque foi um comando de terminal. Peça ao Claude para renomear de volta e anote a lição: **para desfazer qualquer coisa, só o Git resolve.**

> **No Desktop / No VS Code:** o modo fica no **seletor de modo** (Desktop) ou no **indicador de modo** (VS Code). As regras de `/permissions` são as mesmas, porque ficam nos arquivos de configuração da pasta.

## Pergunta de fixação

Você pediu ao Claude para apagar uma pasta com um comando de terminal e se arrependeu. O rewind resolve? O que resolveria?
